# Design: Tier 1 Qwen brain switch

Date: 2026-11-25
Status: Approved in brainstorming; implementation not started.

## Context

Tier 1 currently runs **Gemma 4 E2B QAT Q4_0** through bundled `llama.cpp` b12676. The local GGUF is 3.3 GB and exceeds GitHub's 2 GB LFS per-file limit, so it is ignored and must be supplied manually. A separate 0.94 GB `mmproj` file is currently required by the runtime path validator and always passed to `llama-server`, even though Tier 1 makes no image claim.

The approved direction is to replace the Tier 1 default with **Qwen3.5-2B Q4_K_M** from `axteam/Qwen3.5-2B-GGUF`. That file is 1.3 GB, text-only, Apache-2.0, and fits under the LFS cap. It can therefore be tracked in the repository, removing the manual GGUF supply step.

The WPF pet layer is unaffected. Breathing, sway, idle actions, face patterns, and expanded-screen motion are deterministic .NET/WPF behavior in `src/Slop.Motion.ps1` and `src/Slop.ps1`; they are not generated by the language model. Response timing may vary slightly, but no animation code changes.

## Goals

- Replace the default Tier 1 brain with Qwen3.5-2B Q4_K_M.
- Remove the mandatory `mmproj` requirement for the default text-only path.
- Keep the endpoint, SSE reader, cancellation, voice path, and permission surface unchanged.
- Track the 1.3 GB GGUF with the existing LFS rules; remove the Gemma-specific ignore entry.
- Update tests, labels, docs, and third-party notices to match the new brain.
- Prove the wiring with focused RED/GREEN tests and a live **text** smoke using `SLOP_LIVE_RUNTIME_DIR` plus `SLOP_LIVE_MODEL_FILE`.

## Non-goals

- No new brain supply mechanism beyond approved LFS tracking.
- No Tier 2, OpenCode, provider, or route-policy change.
- No thinking-mode default change; Qwen3.5-2B stays non-thinking.
- No image, audio, VAD, TTS, or spoken-reply claim.
- No config schema version bump; existing fields are reused.
- No live mic/Whisper claim without real mic, `whisper-cli.exe`, and `ggml-small.bin`.
- No push, deploy, or remote change.

## Decision

Use the recommended approach from brainstorming: **replace the Tier 1 default and LFS-track the Qwen GGUF**. Alternatives were rejected because keeping Gemma as default preserves the packaging problem, keeping Qwen manually supplied discards the main benefit, and maintaining two profiles adds complexity without a default win.

## Architecture and components

### Config contract (`src/Slop.Config.ps1`)

Keep the existing field names; no v3 migration:

- `localModelName` → `Qwen3.5-2B Q4_K_M`
- `localModelFile` → `models\Qwen3.5-2B-Q4_K_M.gguf`
- `localMmprojFile` → empty string, meaning unused readiness hook

Validation and backfill remain structurally the same. An empty `localMmprojFile` is valid. A configured-but-missing mmproj remains an error.

### Runtime (`src/Slop.LocalModel.ps1`)

- Update `Get-SlopRuntimePaths` default model path and mmproj default to empty.
- Update `Get-SlopBundledModelName` to return `Qwen3.5-2B Q4_K_M`.
- Update `Test-SlopLocalModelPaths` so server + model are required, while mmproj is checked only when configured.
- Update `New-SlopLlamaArguments`:
  - Always include `--model`, `--host`, `--port`, `--ctx-size`, `--cache-ram`, `--threads`, `--n-predict`, and `--alias`.
  - Include `--mmproj` only when the resolved mmproj path is non-empty.
  - Include `--jinja` for the local llama-server path so the GGUF's embedded chat template is used.
- Keep allowed context sizes at `8192`, `16384`, and `32768`. Qwen's native 262K window is not worth the memory and UX change for this companion.

### Route and UI labels

- `src/Slop.Route.ps1` continues to read model name/path from config and `Get-SlopBundledModelName`; no new routing shape.
- `src/Slop.ps1` static XAML fallback and runtime fallback become `Local · bundled · Qwen3.5-2B Q4_K_M`.

### Tools

- `tools/slop-preflight.ps1`: label `Qwen model`; check mmproj only when configured.
- `tools/verify-motion.ps1`: stand-in model path becomes the Qwen filename; `SLOP_LIVE_RUNTIME_DIR` and `SLOP_LIVE_MODEL_FILE` remain required stand-ins, while `SLOP_LIVE_MMPROJ_FILE` becomes optional and is linked only when supplied.

### Data flow

Unchanged pipeline:

`config → Get-SlopRuntimePaths → Test-SlopLocalModelPaths → route badge → New-SlopLlamaArguments → llama-server /v1/chat/completions → existing OpenAI-compatible SSE adapter`

`src/Slop.Adapter.OpenAi.ps1`, `src/Slop.Lifecycle.ps1`, `src/Slop.Provider.ps1`, and cancellation behavior are not modified.

## Error handling

- Missing `llama-server.exe` or model file: existing explicit error.
- Empty `localMmprojFile`: valid; no `--mmproj` argument and no preflight failure.
- Non-empty but missing mmproj: explicit error, as today.
- Invalid context size: falls back to `8192`, as today.
- Non-loopback health URL: rejected by existing `Test-SlopLocalModelHealth`.

## Tests and verification

RED first in these suites:

- `tests/slop-config-check.ps1`: defaults and empty-mmproj validity.
- `tests/slop-localmodel-check.ps1`: Qwen path defaults, no `--mmproj`, present `--jinja`, unchanged context clamping.
- `tests/slop-route-check.ps1`: Qwen badge from config and helper.
- `tests/slop-shell-check.ps1`: static fallback badge and the preserved README phrase `opt-in push-to-talk audio is transcribed locally`.
- `tests/slop-preflight-check.ps1`: Qwen model stub path and optional mmproj.

Then:

1. Run the focused suites GREEN.
2. Run the canonical repo-root Pester verify gate.
3. Run the tour anchor check after source line shifts.
4. Run `git diff --check`.
5. Run a live **text** smoke with `SLOP_LIVE_RUNTIME_DIR` and `SLOP_LIVE_MODEL_FILE` (Qwen GGUF), and without `SLOP_LIVE_MMPROJ_FILE`. Voice smoke remains deferred.

## Packaging and notices

- Existing `.gitattributes` rule `runtime/**/*.gguf filter=lfs diff=lfs merge=lfs -text` already covers the new file.
- Remove the Gemma-specific entry from `.gitignore`; do not ignore the Qwen GGUF.
- Add `Qwen3.5-2B` and the `axteam` GGUF quant to `docs/third-party-notices.md`, with Apache-2.0 provenance.
- Update README, `docs/architecture.md`, `docs/bundling-and-first-run-plan.md`, and research notes. Keep the existing honest voice wording; change the brain name and supply path only.

## Risks and trade-offs

- Qwen's non-thinking card scores are slightly lower than Gemma E2B on general-knowledge benchmarks such as MMLU-Pro and MMMLU. For short companion replies this is acceptable; the packaging win is the point of the switch.
- The axteam GGUF is text-only. Tier 1 already makes no image or audio claim, so this is not a regression.
- Qwen supports thinking mode, but enabling it would change latency and response feel. It stays off.
- LFS storage grows by 1.3 GB, but the oversized 3.3 GB file is no longer part of the default supply path.
- A live text smoke is required; headless tests alone do not prove the model serves the new architecture through b12676.

## Acceptance criteria

- Default config and route badge name Qwen3.5-2B Q4_K_M.
- Default runtime requires server + model but not mmproj.
- Generated llama args contain `--jinja` and omit `--mmproj` on the default path.
- Qwen GGUF is LFS-tracked; Gemma-specific ignore line is gone.
- Focused suites, canonical verify, tour anchors, and diff check pass.
- Live text smoke passes with the stand-in or real Qwen GGUF.
- Voice behavior, WPF animations, Tier 2 route, and permissions are unchanged.
- No push or deploy occurs.
